# Durable telemetry journal: implementation and limits

Updated 2026-10-06. Supersedes the live-delivery design in historical Phase 6/9 notes.

Read-only pending-record inspection now pages by local journal sequence across
protocols, with at most 1,000 records and 8 MiB per page. It decrypts exact original
bodies without acknowledgments, retirement, eviction or transport receipts. The
cursor describes physical journal order, not canonical endpoint sequence, and
separate calls are not an atomic snapshot under live writers/uploaders. Sequence
holes from acknowledgments are preserved; oversized heads and invalid cursors
fail explicitly. The owned stopped-runtime recovery probe pages to exhaustion,
checks the original pending count, and bounds its aggregate read to 10,000 records
and 64 MiB. This removes the verification reader's single-transport-batch ceiling
without shrinking endpoint captures or changing uploader batch limits. Live
inspection consistency, protected operational export and corrupt-row isolation
remain separate qualification work.

`Uploader::enqueue` stores one observation synchronously and returns true only after SQLite commits. There is no volatile unbounded pending vector. Network requests run on a separate worker. Stop initiates no final network drain; an in-flight request remains subject to WinHTTP operation timeouts, not yet a single end-to-end deadline. Decoded events now use a bounded volatile worker handoff before normalization/journaling; callback return is not a durable acceptance receipt. Native decode, durable handoff intent and full callback/deadline qualification remain open. See [callback handoff](CALLBACK_HANDOFF.md).

The Windows SDK `winsqlite3` provides SQLite. Startup requires WAL, sets `synchronous=FULL`, checks schema version and performs `quick_check`. A damaged database fails explicitly and is preserved. Durability relies on Windows/storage honoring flushes; physical power-loss qualification remains open. Microsoft documents [OS-shipped SQLite](https://blogs.windows.com/windowsdeveloper/2017/02/06/using-sqlite-databases-uwp-apps/); see SQLite's [WAL](https://sqlite.org/wal.html) and [synchronous setting](https://sqlite.org/pragma.html#pragma_synchronous).

Bodies and rejection reasons use user-scoped DPAPI with the record key as entropy. The journal belongs to its creating Windows account; account changes require controlled export/migration. Protected DACLs grant owner, SYSTEM and administrators on the directory and existing DB/WAL/shared-memory files. Inspected reparse paths are rejected. Filesystem races, hard-link/handle-based protection and installer-owned provisioning remain open; this is not protection against a compromised administrator. Legacy files remain untouched and may contain plaintext; their retention/removal requires the controlled migration lifecycle.

Default retention is 16 GiB of observation/rejection-reason plaintext payload. Exhaustion explicitly refuses new acceptance and retains existing pending/rejected evidence. This is **not a physical filesystem hard limit**. A separate sampled admission safeguard defaults to 32 GiB of DB/WAL/SHM logical file lengths and 128 MiB of minimum caller-available volume space. Before growing writes it requires an additional allowance of 128 KiB plus four times encrypted payload bytes (metadata uses its bounded input size). This allowance is conservative engineering policy, not a proven maximum SQLite write amplification. Windows reports caller-available bytes subject to the calling identity's quota; see [GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw).

Physical preflight covers new observations, command bodies/outcomes/transitions, rejection reasons, identifier/generation changes and legacy import metadata. Identical observation/command/retained outcome retries and reads do not require growth admission. Valid acceptance ACKs can delete acknowledged rows under pressure; rejection metadata refusal rolls back the whole receipt, preserving pending originals. Failed size/free-space queries refuse growth rather than substituting zero or pretending the query succeeded. File lengths measure logical size, not allocated clusters. Startup schema/integrity work and ACK deletion/checkpointing can still write. Samples race volume changes/other writers, and multi-row transactions can grow beyond the estimate. Legacy originals and other inbox/outbox directories are outside this per-journal sample. Hard physical/aggregate budgets, reserve allocation, durable full-disk loss accounting and fault qualification remain open. No 24-hour offline capacity claim has been qualified.

Online and offline runtime health expose admission limits, quota-aware available bytes and current-object refusal counts as exact decimal strings. Safeguard coverage stays degraded because reservation and aggregate accounting are absent; failed stats queries expose unavailable with the failure reason. Refusal counts reset on object recreation and are not a durable loss ledger. The short 1,000-event benchmark with preflight measured approximately 1,031 events/s (p95 commit 1.046 ms) on this host, below the approved 2,000 events/s target. It is not a paired regression experiment or storm/soak qualification.

HTTP 200 alone acknowledges nothing. Protocol-1/2 receipts must match batch ID and submitted count, fully partition accepted/duplicate/rejected observations, use unique in-range rejection lines, and match supplied event/record IDs to those lines. Invalid/partial receipts leave the batch pending. Valid receipts atomically remove acknowledged rows and retain encrypted rejected originals/reasons, inspectable through `dead_letters`. Network/TLS/server/authentication failures retain pending data indefinitely with bounded retry backoff. Audited dead-letter reprocessing remains open.

Migration ignores the old cursor and reads complete frames without modifying source files. Imported observations preserve exact bytes and receive deterministic filename/offset/line/payload-derived IDs. An import ledger prevents reimport after delivery/restart. Corrupt/torn framing produces durable gap metadata; an untrustworthy length ends that file's scan without guessing alignment. Advanced recovery and a forensic manifest remain open.

Journal schema 2 adds protocol routing and persistent installation identity. Schema 3 adds immutable encrypted command admission, committed execution intent, encrypted outcomes and retained replay tombstones. Existing schema-1/2 journals upgrade in place without deleting observations; legacy segments still import without modification. The plaintext ceiling now includes command bodies and results alongside observations/rejection reasons; the independent response inbox/outbox quotas are not a shared physical-disk budget. See [command inbox](COMMAND_INBOX.md). Canonical and legacy observations never share a transport batch. Capture is durable even without a Manager URL; `--spool-directory` controls the protected data location. Relative default location and final installer-owned service data provisioning still require qualification.

HTTPS remains mandatory when explicit development certificate validation bypass is enabled. Redirects are disabled. Request/response buffering is bounded and response-read failures cannot become successful end-of-stream. Existing enrolled credentials are loaded before collector output and attached to delivery. Bootstrap remains coupled to the existing response enrollment path; rotation/revocation and secure credential migration remain unfinished. The isolated real WinHTTP-to-Manager HTTPS fixture test passes, including durable receipts and latest health/state readback. Live sensor, fleet and full operational E2E are unqualified.

Component tests exercise orderly and abrupt-process-exit recovery, byte preservation, absence of plaintext bodies in DB/WAL, duplicate enqueue, malformed/wrong/incomplete receipts, rejection association and encrypted inspection after restart, quota refusal without eviction, torn legacy tails and idempotent migration. Reboot/power-loss, disk-full/I/O faults, simultaneous writers, storms, live E2E and performance qualification still remain.
