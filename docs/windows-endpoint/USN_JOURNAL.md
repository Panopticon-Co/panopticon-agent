# Native USN journal fallback

The endpoint independently reads existing local volume change journals through FSCTL_QUERY_USN_JOURNAL and FSCTL_READ_USN_JOURNAL. It discovers at most 16 native volume GUID paths at startup and gives each admitted volume an independent worker and durable source key. It never creates, deletes, resizes or enables a journal, enables privileges, or changes filesystem policy. Hotplug rediscovery and volume clone/replacement reconciliation remain incomplete.

Each newly observed source records an explicit durable gap and starts at the native current tail. Existing file state and history before that baseline are unobserved. On subsequent source restart, the worker loads its encrypted cursor, preserving the native journal ID and signed nonnegative next USN without floating point conversion. Journal instance replacement, a saved cursor before the retained/valid range, or a cursor ahead of the journal produces a durable gap plus a replacement cursor at the earliest retained valid position. These are discontinuities with unknown event loss, not exact dropped-event counts. Malformed saved cursors fail closed and remain blind; they are not silently reset.

A batch's original canonical bytes and next source cursor enter the existing FULL/WAL checkpoint transaction together. Acceptance refusal retries that same immutable record without another source read or cursor advancement. Source checkpoint revision and next cursor are retained in the evidence body; health binds the last committed record ID, source, journal ID, next USN and revision. A missing or failed transaction does not authorize advancement. Pending bytes and collector counters are volatile; abrupt-exit unaccepted data loss is unknown. Existing journal retention can expire while the endpoint is stopped or blocked by disk pressure; recovery checks those bounds before resuming.

The bounded decoder retains complete native read buffers and parses V2/V3 records with version-specific fixed-field offsets and runtime record/name spans. It preserves 64/128-bit native file and parent IDs as exact native byte hex, signed USNs/timestamps, reason/source/security/attribute masks, filename UTF-16 bytes and strict UTF-8 where valid. Invalid UTF-16 remains raw with null text. Unsupported versions remain opaque. Native record timestamps stay signed FILETIME evidence; envelope/event boot identity is not inferred from historical records. Batches use common endpoint envelope 1.0 with OS-specific bodies and null process subjects. They make no actor, full-path, content-integrity, creator or rename-pair claim.

The native reader requests V2/V3 with all reason bits and ReturnOnlyOnClose/Timeout/BytesToWaitFor zero. Version-4 extent coverage remains unverified; a negotiated version range is not a claim that every kind of change was delivered. Decoder/copy refusals retain the complete native buffer with semantic blindness instead of silently discarding evidence and advancing. No file-content hash or current-path lookup is substituted for the original journal facts.

Application controls: at most 16 workers, a fixed 16 KiB native read buffer per source, 512 KiB decoded body admission and at least one second between successful read cycles. Journal disk admission/backpressure applies independently. A stalled source poll becomes blind after ten seconds. Native operations and shutdown joins do not yet have a hard deadline/allocation cap. Aggregate byte fairness, sustained backlog, internal spool-write feedback, CPU/disk/soak controls, removable-volume changes, privacy/redaction and native fault qualification remain open. Own spool changes can appear in the volume journal; no unsafe basename exclusion is applied.

Host tests verify native buffer layouts, canonical cursor bounds, unknown versions, malformed lengths/alignment/name spans, invalid UTF-16 and null attribution. Non-elevated host live access is correctly refused (Win32 5), so a host test pass does not prove a live journal read. Elevated dedicated-guest tests require actual file/ADS/rename/delete reasons, immutable refused commits, independent held-file index agreement and replay of a file created while the source is stopped. The separate endpoint runtime harness exercises its own unique benign file mutations and abrupt-exit original recovery. See VALIDATION.md for actual outcomes; full filesystem/FIM/minifilter/USN fault/OS qualification remains unmet.

Elevated checkpoint follow-up additionally verifies replay after closing/reopening the durable journal, saved journal-ID mismatch, ahead/before-retained cursors and malformed cursor blindness using isolated owned stores against unchanged native volume journals. Independent evidence verification checks actual native bounds and gap classification. This does not induce or qualify real journal rotation/retention pressure or a full endpoint service restart. See the validation ledger for the exact preserved evidence and remaining gates.
